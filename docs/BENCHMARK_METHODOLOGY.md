# CASCADE: Benchmark Methodology & Technical Verification Audit

This document provides complete, transparent, and reproducible technical specifications for all benchmark results reported for **CASCADE** on **IBM LinuxONE (s390x)** during the **IBM Z Datathon 2026**.

## 1. Pipeline Throughput Benchmark: 9,355.5 events/sec

### The Core Question
> *"Was this the complete pipeline, or primarily event publication? Were events actually processed, scored, persisted, and acknowledged?"*

### Experimental Configuration & Measurement Protocol
- **Target Platform:** IBM LinuxONE Community Cloud Virtual Server (`s390x`, Linux 5.15.0-56-generic, 3 vCPUs, 8 GB RAM).
- **Execution Script:** `python -m eval.latency_report --mode inprocess --duration 60.0`
- **Measurement Script Source:** [`eval/latency_report.py`](../eval/latency_report.py)
- **Raw Data Output:** [`docs/eval/latency.json`](../docs/eval/latency.json)

```
Events Replayed / Published: 718,000
Events Fully Processed & Scored: 556,641
Wall-Clock Scoring Duration: 59.5 seconds
Sustained Scoring Throughput: 9,355.5 events/second
Total Positive Cascade Alerts Fired: 1
```

### Complete End-to-End Processing Path
This throughput measurement is **not** a raw socket or publisher benchmark. For every single one of the 556,641 events, the following complete computational path was executed:
1. **Event Ingestion:** Event dequeued from the streaming buffer in micro-batches of up to 200 events.
2. **State & Lookback Verification:** Lookback query against in-memory patient history hash table (`pstate:<token>`) to identify active candidate index medications started within 1 to 180 days.
3. **Feature Engineering:** Full 16-feature vector extracted (time lag, index drug class, marker drug class, age band, prior cascade count, known list flag, and live Loop 2 population symmetry ratios $\text{aSR}$).
4. **Machine Learning Inference:** Evaluated via XGBoost ($M_1$) constrained by monotonic sequence ratios and regularized logistic blend ($M_2$).
5. **Explainability & Attribution:** When risk exceeds the operational threshold ($\ge 0.74$), the system calculates TreeSHAP feature contributions (`pred_contribs=True`), extracts the top-3 clinical reasons, and ranks the suspected reaction.
6. **Persistence:** Latency metrics (`event_id`, `ms`, `alerted`, `wall_ts`) are written into the database latency ledger.

## 2. Loop 1 Latency Distribution: 6.0 ms Median

### The Core Question
> *"Does this include queueing, feature extraction, inference, explanation, and database operations, or only model scoring?"*

### Measurement Points & Definition
Latency is measured inside [`loop1/score_service.py`](../loop1/score_service.py#L137):
$$\text{Latency} = t_{\text{decision}} - t_{\text{read}}$$
- **$t_{\text{read}}$ (Start):** The exact monotonic timestamp recorded when a batch of up to 200 events is read from the stream buffer.
- **$t_{\text{decision}}$ (Stop):** The timestamp when candidate feature evaluation, XGBoost inference, TreeSHAP explanation ranking, and alert payload assembly are completed for that event.
- **Queueing Inside Batch Included:** Because events in a micro-batch are processed sequentially, events near the end of a 200-event batch reflect the queueing latency of preceding events in that batch.

### Empirical Latency Distribution (Measured on LinuxONE s390x)
```
p50 (Median):       6.001 ms
p95:               7.068 ms
p99:              33.902 ms
Maximum Observed: 37.993 ms
```

> **Why Tail Latency Spikes to 33 ms at p99:** Under sustained maximum publishing speed, the consumer micro-batch buffer reaches capacity (200 events). An event processed at index 199 waits for feature computation of indices 0–198, representing realistic system load under peak national dispensing bursts.

## 3. Real-Time Scorer Accuracy: 81.5% Precision & 98.0% Recall

### The Core Question
> *"How were the labels established? Were training and evaluation data sufficiently independent? How representative are the synthetic examples?"*

### Data Provenance & Temporal Independence
To avoid data leakage, all data was strictly partitioned using a **temporal holdout split** across 3 simulated years:
- **Training Set (Years 1 & 2: 2023-01-01 to 2024-12-31):** Used for fitting XGBoost tree ensembles and logistic regression parameters.
- **Validation Set (Year 3, Q1–Q2: 2025-01-01 to 2025-06-30):** Used exclusively for tuning blend weights and fixing the operational alert threshold ($\tau = 0.74$).
- **Test Set (Year 3, Q3–Q4: 2025-07-01 to 2025-12-31):** Evaluated strictly once. **Zero model weights, feature definitions, or decision thresholds were tuned on test data.**

### How Labels Were Established
- **Positive Labels ($y=1$):** Prescriptions generated by the causal cascade injection engine ([`datagen/inject.py`](../datagen/inject.py)), simulating an adverse reaction to Drug A that led a physician to prescribe Drug B.
- **Negative Labels ($y=0$):** 
  - Independent coincidental co-prescribing events (patient happened to start Drug B after Drug A for unrelated clinical reasons).
  - Isolated monotherapy dispensing events.
  - Symmetric dual-starts (same-day co-prescriptions with zero temporal gap).
- **Hidden Novel Cascade (H1):** Fictional drug *Novacor* (C09XX) causes dyspepsia/gastritis treated with Pantoprazole (A02BC). **H1 had ZERO positive training labels.** It was evaluated solely on the test set to prove zero-shot statistical detection.

### Test Set Performance Breakdown (Test Period: 20,072 Candidate Pairs)

| Model Configuration | Precision | Recall | F1 Score | PR-AUC | Threshold | TP / FP / FN / TN |
|---|:---:|:---:|:---:|:---:|:---:|:---:|
| **Operational Blend (All Cascades incl. H1)** | **0.815** | **0.980** | **0.890** | **0.9106** | **0.740** | **393 / 89 / 8 / 19,582** |
| Blend (Known Cascades only) | 0.548 | 0.981 | 0.703 | 0.9455 | 0.740 | 264 / 218 / 5 / 19,585 |
| XGBoost alone ($M_1$) | 0.540 | 0.952 | 0.689 | 0.5536 | 0.914 | 256 / 218 / 13 / 19,585 |
| Logistic Regression alone ($M_2$) | 0.554 | 0.342 | 0.423 | 0.4968 | 0.961 | 92 / 74 / 177 / 19,729 |
| **Ablation:** Without Known Prior (`pair_in_known_list = 0`) | 0.533 | 0.959 | 0.685 | 0.7549 | 0.872 | 258 / 226 / 11 / 19,577 |
| **Ablation:** Without Live PSSA Signals (`pair_aSR_* = 0`) | 0.821 | 0.647 | 0.724 | 0.6845 | 0.765 | 174 / 38 / 95 / 19,765 |

> **Why Known Labels Only Shows 54.8% Precision:** When evaluating known labels only, all 132 alerts on the novel cascade H1 (*Novacor* &rarr; PPI) are treated as "False Positives" because H1 was deliberately omitted from the training label set. When ground truth accounting includes H1, true operational precision is **81.5%** with **98.0% recall**.

## 4. Hardware Cryptography Benchmark: 13.3 GB/s Throughput

### The Core Question
> *"Which operation was benchmarked, with what block size and configuration? Is that result attributable to the hardware cryptographic path?"*

### Benchmark Specification
- **Command Executed:** `openssl speed -evp aes-256-gcm -seconds 3` directly on the IBM LinuxONE Community Cloud VM (`s390x`).
- **Cryptographic Mode:** Authenticated encryption using AES-256-GCM via the OpenSSL EVP interface.
- **Hardware Instruction Path:** IBM z/Architecture CPACF Message-Security-Assist (`msa`) instructions executing `KMA` (Cipher Message with Authentication).

### Raw Output Across Block Sizes
```
Block Size     Throughput (kB/sec)    Throughput (MB/s or GB/s)
----------------------------------------------------------------
16 bytes           229,634.17 kB/s       ~229.6 MB/s
64 bytes           875,487.63 kB/s       ~875.5 MB/s
256 bytes        2,957,287.77 kB/s       ~2.95 GB/s
1,024 bytes      8,449,238.80 kB/s       ~8.45 GB/s
8,192 bytes     13,284,729.56 kB/s      ~13.28 GB/s
16,384 bytes    13,304,194.15 kB/s      ~13.30 GB/s
```

### Verification of Kernel Hardware Driver
Inspecting `/proc/crypto` on the LinuxONE host confirms that the Linux kernel registers dedicated s390 hardware acceleration drivers at top priority:
```
driver   : gcm-aes-s390  (priority 900)  <-- Hardware CPACF GCM
driver   : aes-s390      (priority 300)  <-- Hardware CPACF AES
driver   : aes-generic   (priority 100)  <-- Software Fallback (not used)
```

### What This Establishes & What It Does Not Establish
- **What It Establishes:** CPACF cryptographic instructions are present, active, and capable of executing authenticated AES-256-GCM encryption at line rates exceeding 13 GB/s on the s390x processor.
- **What It Does Not Establish:** It does not imply that application-level database operations take zero time. Database writes still incur SQLite/PostgreSQL transaction and storage overhead, which CASCADE mitigates through asynchronous write pooling (`asyncio.to_thread`).

## 5. GenAI Evaluation & Blinded Clinical Pharmacist Review

### The Core Question
> *"What exactly counted as a hallucination? Who reviewed the ten reports, and what did the test fail to cover?"*

### Evaluation Protocol
- **Sample:** 10 diverse alert scenarios from the test set (`EV-001` to `EV-010`), covering classic ThinkCascades pairs, novel cascades (Novacor &rarr; PPI), cross-physician fragmentation, and geriatric age bands.
- **Backend Tested:** `GENAI_BACKEND=lab` (Ollama Llama 3 via `/v1/chat/completions`) with deterministic AST template fallback.
- **Reviewer:** Conducted by clinical pharmacists using standardized review criteria recorded in [`docs/eval/genai_human_review.csv`](../docs/eval/genai_human_review.csv).

### Operational Definition of Hallucination
In CASCADE's clinical validator, an output is classified as a **hallucination or critical failure** if it:
1. Names a drug or medical reaction not present in the structured input contract.
2. Fabricates numeric values (e.g. inventing a time gap different from the input data).
3. Uses prohibited assertive diagnostic language (e.g., claiming "this drug caused the reaction" rather than "possible prescribing cascade").
4. Uses coercive prescriptive imperatives (e.g., "you must stop", "discontinue immediately").
5. Omits the mandatory non-punitive review request to the prescriber.

### Review Results Breakdown
- **Directly Usable (Zero Edits Needed):** 9/10 (90%) — Clear, polite, clinically non-accusatory tone with exact drug names and latency days.
- **Needs Minor Edit:** 1/10 (10%) — `EV-002` had a minor prompt token placeholder (`[index_drug]`) that was caught before transmission.
- **Clinically Incorrect / Hallucinated:** **0/10 (0%)** — Zero medical hallucinations; zero banned prescriptive directives.
- **Validator Pass Rate:** **100.0%** — All 10 drafts passed schema validation and content constraints (using template fallback on 8 drafts and direct LLM generation on 2 drafts).
